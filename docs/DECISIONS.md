## M2 — 2026-10-08

| # | Decision | Why |
|---|----------|-----|
| 36 | Sync: the device keeps `{userId, version}` beside its save. On start, on return to the foreground, every 30 s and on hide (`keepalive`), it uploads with `baseVersion`. A stale version gets a 409 plus the server copy, which replaces the local farm and is caught up to now | "Server copy wins" from the design doc. At most ~30 s of play on a second device is lost. |
| 37 | A farm never synced (played before logging in) is claimed by the first player who logs in, but only if they have no server farm yet. Otherwise their server farm loads. A device that changes player loads that player's farm, or a new one | The M1 farms on Pavel's phones carry over. Nobody inherits someone else's farm. |
| 38 | If the server has no copy but the device has synced before (database wiped), the device re-uploads its farm as version 1 | A server restore never erases phones. |
| 39 | Plausibility (`shared/src/sim/validate.ts`): **wealth** = lifetime coins + barn at 2× base price; only production raises it. Wealth growth ≤ 2 × (best-crop rate on every field + animals + 15 taps/s) × elapsed + one harvest per field. Orders are capped by item production, XP by harvests plus orders (paid at the level reached). Owned upgrades must be covered by lifetime coins. Elapsed uses the save's clock capped at server time + 2 min; a first upload may claim at most 7 days | One rule covers coins, barn, selling, orders and the mill without replaying actions. Tests run the bot through 2–3 days with uploads every 30 s or 6 h, and nothing is ever clamped. |
| 40 | Clamping removes the excess from coins first, then unbacked lifetime coins, then the most valuable barn items, and sends the clamped farm back. A farm whose upgrades were never paid for is rejected (422) and replaced by the last server copy | Pavel's exit criterion: "a doctored save is clamped." Doctored upgrades can't be clamped back sensibly. |
| 41 | `stats` is updated on every accepted save. Week coins = lifetime-coin growth since the previous save, kept per Prague week (`weekKey`, Monday 00:00 Europe/Prague) | Avoids a cron reset. A stale week reads as 0. |
| 42 | All six boards are live. Today, Minigames, Collector and Medals say "coming in a later update" until M3/M5 fill `daily_results`, `best_scores` and the stats columns, whose tables already exist | The UI and API are final now; later milestones only add data. |
| 43 | Ties share a rank (1, 1, 3). The family is every user in the database, so the boards show only people Authelia let in | Three players; no separate roster to maintain. |
| 44 | Family bar = chips under the HUD (initial in a coloured circle, first name, level). Tapping opens the boards; visiting villages comes in M4. Logged out, it shows a "Log in to play with the family" chip | Avatars are a design-doc open question; initials work until then. |
| 45 | Bottom bar has 5 buttons (Boards added, with a generated trophy sprite) | Boards need a one-tap home. |
| 46 | `DEV_LOGIN=1` (never in production) adds `GET /auth/dev?as=name` for multi-player e2e | Playwright can't log in through Authelia. |
| 47 | Locale stays per-device in localStorage (deferred from #33) | Each player has their own phone; nothing server-side needs the locale until M4 notifications. |
| 48 | `buzz()` checks `typeof navigator.vibrate === 'function'` and never throws | WebKit has `vibrate` with the value undefined. The old guard threw on iPhone in the middle of the tap handler, which stopped the tutorial from advancing. Found by the M2 iPhone e2e. |

## M3 — 2026-10-08

| # | Decision | Why |
|---|----------|-----|
| 49 | Every minigame is a pure `Game<S, M>` in `shared/src/games`: `init(seed)` builds the board and `move(state, move, ms)` applies an input. Neither reads the clock or `Math.random`. The client plays through `GameSession`, which records `[ms, move]`; the server runs `replay()` through the same session code | One engine on both sides, so the scores can't disagree. M3 exit test: client and server scores are identical for 1000 random seeds × 5 games. |
| 50 | Kid-sized boards. **Pexeso** 4×4 (8 farm pairs). **Water Pipes** 4×5 random spanning tree, scrambled, never starts solved. **Crop Merge** 2048 on 4×4, 3 min, tiles seed → sprout → wheat → … → trophy. **Harvest Rush** 3×4 plots, 30 s, every pop-up decided by the seed up front (70 % ripe / 15 % unripe / 15 % weed, 1.7 → 1.2 s on screen). **Egg Sort** 4 kinds × 4 eggs in 6 baskets, each board checked solvable by a DFS solver | Tests: a slow player (one move every 2 s, 0.7 s reactions in Rush) finishes every Pexeso, Pipes and Egg Sort board in 1000 seeds within the limit. |
| 51 | Scores: finishing pays a base, plus a bonus for few extra moves and for speed (max 1500). Unfinished games score partial progress. Rush: +10 per ripe crop, +2 per tap in a streak (up to +10), −5 for a weed or sprout | Every game rewards finishing first, then doing it well. |
| 52 | Rewards: q = score ÷ the game's par, clamped to 0.1–1.5. Coins = q × max(30, 90 s of the farm's base income); XP = q × 2 order-XP at the player's level. Computed on the server from the last synced farm. 5 rewarded free plays per game per day, then practice. The daily ranked try pays ×2 and doesn't count towards the 5 | Rewards scale with the farm, so they stay meaningful from level 1 to prestige, and a rough game still pays a little. |
| 53 | Saves go to v2: `lastRewardId` and cumulative `stats.rewardCoins/rewardXp`. The farm's `reward` action applies a server-granted reward once. `checkSave` allows exactly the rewards granted since the previous save, and clamps claimed rewards above the server ledger (`minigame_plays`). v1 saves migrate on load | Minigame coins don't come from farm production, so the plausibility clamp needs a ledger to accept them. |
| 54 | Daily: the game rotates by Prague day number mod 5, and the seed is HMAC-SHA256(`DAILY_SECRET`, defaulting to `SESSION_SECRET`, YYYY-MM-DD). `POST /api/daily/start` hands out the seed once and uses up the ranked try. Ending a daily early submits it as it stands; closing the app mid-game leaves it unfinished, with no score that day. A result is accepted up to the game limit + 10 min after the start, even past midnight | The design's "first attempt is the ranked one"; the seed can't be fetched to practise on first. |
| 55 | Crown: yesterday's best finished daily score (earliest finish wins a tie) wears the crown today, on the family bar and the games sheet. The collectible part of the prize waits for M5's Collection Book | Collections don't exist yet. |
| 56 | Minigames are DOM boards over the farm, not Phaser scenes. Quitting needs two taps; free-play quits aren't submitted | Grid games are simpler and crisper as DOM; the double tap protects the kid's ranked try. |
| 57 | Bottom bar: Shop, Barn, Orders, **Games**, Boards. Settings moved to a gear at the end of the family bar | Games deserve a one-tap home for the kid; settings are rarely used. |
| 58 | Free play works logged out or offline as practice (no reward) | Rewards need the server to replay the log. |
| 59 | The farm container uses 1.1.1.1 and 8.8.8.8 as DNS servers (`deploy/compose.yml`) | On 2026-10-08 the router's DNS returned SERVFAIL for every name, so the server couldn't reach Authelia and new logins failed. |

## M4 — 2026-10-08

| # | Decision | Why |
|---|----------|-----|
| 60 | Visiting reuses the farm scene: `FarmScene.view(state)` draws the other player's last synced farm, read-only, and catches it up to now every second so their farmhands keep working. The HUD and bottom bar hide, and the family bar stays so you can hop between farms. Tapping your own chip opens the boards; anyone else's opens their village | One renderer, so a visited farm looks exactly like the owner's. |
| 61 | A visit is recorded when the village opens (`POST /api/visits`). At most one sticker per visit (`POST /api/visits/:id/sticker`, 409 after that). Six stickers: heart, flower, sun, smile, star, cow | The design's "one sticker reaction per visit"; stickers are the only social expression, with no free text. |
| 62 | Gifts: an item from your own barn or a free flower. 3 per sender per recipient per Prague day. One gift ≤ 10 % of the sender's hourly base income (minimum 20 coins). The server checks the barn against the sender's last upload, so the client uploads right before sending. The farm's `giftSend`/`giftClaim` actions move the items | The caps from the design doc. Checking against the last upload needs no extra state on the server. |
| 63 | Gifts are claimed one tap at a time (or "Take all"); flowers count into `stats.flowers` for M5's collections. Save v3 adds `giftValueIn/Out` and `flowers`. Claimed gift value is a server ledger the plausibility check accepts, like minigame rewards | Received items would otherwise be clamped as impossible production. |
| 64 | Mailbox = a chip with an unread badge in the family bar: unclaimed gifts plus visits not yet seen in the last 7 days. Opening it marks visits seen. Gift and visit notifications open the app at `/?open=inbox` | One place for everything social. |
| 65 | Notifications go through the `jobs` table and a 1-minute ticker (only when VAPID is configured). **gift**: as soon as quiet hours allow. **visit**: one pending job per player, sent ≥ 1 h after the previous visit message, naming everyone who came since (+ "and left a sticker"). **ready**: re-planned on every accepted save for the moment all hand-planted fields are ripe; skipped if the player synced after that moment; at most 2 sent per Prague day | The design's three rules; "played since" avoids nagging someone who's already harvesting. |
| 66 | Prefs per player (not per device) in `users.prefs_json`: each type on/off plus quiet hours (whole hours in the settings UI, default 20:00–08:00 Prague). A job due during quiet hours moves to their end; a job already queued is re-checked at send time | The design says prefs are per player. Re-checking covers prefs changed after queueing. |
| 67 | Push texts are written on the server in the player's stored locale (cs/en) | The service worker shows them as sent. |

## M5 — 2026-10-08

| # | Decision | Why |
|---|----------|-----|
| 68 | Prestige ("Move to new land") resets coins, run coins, XP/level, tap level, land, fields, barn, animals and helpers. It keeps lifetime coins, Golden Seeds, perks, the Collection Book, skins, trophies and all stats. Seeds = floor(√(run coins ÷ 1 M)), as designed. The move needs a run worth **15** seeds, and each later move needs **10 %** more (`PRESTIGE` in `shared/src/config/progress.ts`). Two taps to confirm | `pnpm balance`: casual's first move at **4.5 days**, later runs 3.5 → 3.0 → 2.0 days, a geometric mean of about 24 % shorter per run. After that they plateau at 2 days, because the bot only plays at fixed times each day. Kid: 4.0 days. The exit test asserts 4–6 days and a 20–30 % average shrink. |
| 69 | Each Golden Seed *ever earned* adds +2 % to production, including spent ones. Perks cost seeds: Rich soil (+10 %/level, 10 levels), Strong arms (+50 % tap/level, 5), Night shift (48 h offline cap), Old friend (start a run with 1–2 farmhands), Busy market (4th order slot), Lucky clover (+50 % drop chance/level, 3) | Spending never makes you weaker, which matters for a 7-year-old. |
| 70 | "Production" multipliers (seeds × soil perk × collection bonus) speed up crop growth and animal cycles rather than raising prices | Speed already flows through the plausibility check's capacity maths, and sell values stay readable. |
| 71 | The design's +5 % to *adjacent* fields for decorations is simplified: every decoration found gives +0.5 % production and appears in a garden strip below the fields. Each animal kind found gives +1 % | Placing decorations on a grid is a lot of UI for little fun on a phone; the garden still shows them off, also on visits. |
| 72 | 24 animals: 18 common breeds join the book when you own 1–15 of an animal; 6 rare ones (golden hen, black sheep, highland cow, royal bees, piglet, bunny) come from orders, minigames and daily wins. 40 decorations: 14 garden (0.1 % per hand harvest), 14 village (3 % of orders carry one, shown on the card), 8 fair (25 % of rewarded minigame plays, rolled on the server), 4 cups (1/3/6/10 weekly wins). Drops never repeat something already found | Rates from the balance sim: the bot fills everything reachable without minigames in about 2 weeks, so real players will have gaps for longer. |
| 73 | 60 achievements = 20 goals × bronze/silver/gold, computed from lifetime stats rather than stored, so they can't drift. 15 skins: 5 barns and 5 windmills unlocked by medals, 5 fences by playing each minigame 10 times | "Badge on profile": prestige level and medal counts on the family chip and the visit banner. |
| 74 | Save v4 adds `seeds`, `prestige`, `perks`, `found`, `skins`, `trophies`, `lastPrizeId`, and the stats `giftsSent`, `games`, `plays`, `crowns`, `bestLevel/Fields/Farmhands`. v3 saves are upgraded with the breeds they already own. The checks: seeds ≤ √(moves × lifetime ÷ 1 M), moves × 225 M ≤ lifetime coins, and spent + unspent seeds ≤ earned (otherwise rejected). Minigame plays, crowns and trophies are clamped to the server's ledgers | Prestige must survive the plausibility check without letting a doctored save mint seeds. Collection ids are only checked to be real ids: for a family game, faking the book isn't worth more checks. |
| 75 | Prizes (`prizes` table, handed out by the 1-minute ticker and on inbox fetch, up to 7 days or 4 weeks late). **Daily**: yesterday's winner (decided 15 min after midnight) gets an unfound rare animal, else a fair decoration. **Weekly**: last week's top earner(s) in the new `week_coins` table get a trophy. Both arrive in the mailbox with a push (under the "gifts" toggle) and are claimed like gifts. The farm applies them in claim order (`claim_seq`) | One mailbox for everything; per-week coins survive the Monday reset that `stats.week_coins` does. Weekly history starts at this deploy. |
| 76 | Bottom bar gets a 6th button, **Book** (with a dot when a move is possible). Tabs: Animals, Garden (with the trophy cabinet), Buildings (skins), Medals, New land (prestige + perks). Missing items show as silhouettes with a hint on how to get them | The design's Collection Book; prestige lives with the things it keeps. |
| 77 | The balance bot now plants what open orders are missing in its hand-planted fields | Before this it never planted wheat or carrots once better crops unlocked, so it almost never finished an order (9 in 20 days). That distorted every later milestone. |
